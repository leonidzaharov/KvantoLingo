# 🏭 Продакшен-готовность «Кванториума» — что есть и чего не хватает

> Аудит «серьёзной разработки»: слой вокруг кода фич (тесты, CI, безопасность,
> мониторинг). Сделан по фактической проверке проекта. Обновлено: 2026-06-23.

**Главная мысль:** в продакшене это не один навык, а 5–6 разных профессий сразу
(бэкенд, фронтенд, тестировщик, DevOps, безопасник, дизайнер). В командах это разные
люди. Не нужно мастерить всё — нужно знать, что эти слои есть, и закрывать по важности.
Все эти концепции **одинаковы в Python** (pytest, GitHub Actions, Sentry) — изучив их
здесь, знаешь их и для Python.

---

## ✅ Что уже хорошо
- Безопасность входа: bcrypt-хеш PIN, rate-limit (антиперебор), защита от CSRF
  (Fetch Metadata), валидация входных данных (zod) в server actions
- TypeScript + ESLint, проверка переменных окружения (`npm run check-env`)
- HTTPS/CDN на Vercel, миграции БД (Prisma), пулер соединений (Supabase)

## ❌ Чего не хватает (по приоритету)

### 🔴 Уровень 1 — закрыть в первую очередь (недорого, важно)
1. ✅ **Уязвимости зависимостей — СДЕЛАНО (2026-06-24).** Было 10 (2 high, 6 mod, 2 low) →
   стало **6 (0 high, 5 mod, 1 low)**. Обе high закрыты:
   - `npm audit fix` (безопасно) убрал @babel/core, hono, js-yaml, brace-expansion.
   - Next.js вручную поднят **16.2.4 → 16.2.9** (high: DoS/XSS/cache-poisoning). В
     package.json версия была прибита точно, поэтому npm требовал `--force`; сделано
     правкой версии + `npm install`. eslint-config-next тоже → 16.2.9. tsc=0, build зелёный.
   - Связку `prisma/@prisma/dev/@hono/node-server` (3 шт.) добили через npm `overrides`:
     Prisma 7.8.0 жёстко пинит `@prisma/dev@0.24.3` → `@hono/node-server@1.19.11`.
     Добавили `"overrides": { "@hono/node-server": "1.19.14" }` в package.json (заплатка
     в той же ветке 1.19.x, без отката Prisma). 6 → **3**, build остался зелёным.
   - Финальный остаток **3 (0 high, 2 mod, 1 low)** НЕ чиним осознанно: `esbuild`
     (dev-only, приходит из tsx; override на 0.28.x риск сломать tsx) и `postcss`
     (транзитивный ВНУТРИ Next 16.2.9 — уже latest; `--force` тянет next@9.3.3; CSS у нас
     свой, не из пользовательского ввода → реальный риск ≈ 0). Ждут апстрим.
2. **Автотесты** — НЕТ ни одного (есть только ручной `scripts/smoke-test.ts`).
   Нужен фреймворк (vitest) + хотя бы тесты на server actions/геймификацию.
3. **CI (автопроверка при `git push`)** — НЕТ. Серьёзные проекты автоматически гоняют
   lint + build + тесты перед деплоем. Настраивается через GitHub Actions / Forgejo CI /
   Woodpecker (`.woodpecker.yml`) — смотря что на git.haveaniceday.tech.
4. **Мониторинг ошибок** — НЕТ. Если прод упадёт — никто не узнает. Решение: Sentry
   (бесплатный тариф, шлёт уведомление об ошибке).
5. **Заголовки безопасности** — `next.config.ts` пустой. Добавить CSP, X-Frame-Options
   (антикликджекинг), HSTS, X-Content-Type-Options через `headers()` в next.config.
6. **Долг по миграциям БД** — удаление инвентаря шло через `db push` мимо истории
   миграций + дрейф (см. PROGRESS.md / память). Перед след. изменением схемы — ре-baseline.

### 🟡 Уровень 2 — потому что это сайт для ДЕТЕЙ
7. **Данные детей / закон** — храним имена детей и прогресс. РФ: 152-ФЗ «о персональных
   данных»; ЕС: GDPR-K. Минимум — понимать, какие данные храним и зачем; политика
   конфиденциальности. (Это флаг, не юридическая консультация.)

### 🟢 Уровень 3 — полезно, но подождёт
8. Prettier (автоформат), доступность (a11y) для слабовидящих, бэкапы БД (проверить
   план Supabase), аналитика использования, отдельное staging-окружение на Vercel
   (сейчас env заданы только для Production).
